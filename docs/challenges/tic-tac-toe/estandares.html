Estándares y buenas prácticas

04.1

Modelo de Madurez de Richardson — Nivel 2 requerido

0
The Swamp of POX
Un solo endpoint, todo via POST. No aplica.
1
Recursos
URLs distintas por recurso, pero un solo verbo. Insuficiente.
2
Verbos HTTP
Recursos + verbos correctos + códigos semánticos. Mínimo exigido.
Requerido
3
HATEOAS
Links de navegación en las respuestas. Optativo para nota máxima.
Bonus

Aplicación práctica del Nivel 2

  • Verbos correctos: GET para lectura, POST para crear y acciones de dominio, PUT/PATCH para actualizar si aplica.
  • Recursos nominales: las URLs identifican sustantivos (/games, /players), nunca verbos (/createGame, /doMove).
  • Subrecursos para acciones: POST /games/{id}/join, POST /games/{id}/move modelan acciones del dominio.
  • Códigos HTTP semánticos: 201 al crear, 200 en operaciones exitosas, 400 en validaciones fallidas, 403 en acceso no autorizado, 404 si no existe, 409 en conflictos de estado, 422 cuando el estado del negocio no permite la acción, 502/503 en fallos de comunicación entre servicios.
  • Cuerpos de error estructurados: nunca retornar solo el status HTTP; siempre incluir error (código de error) y message (descripción legible).

Buenas prácticas obligatorias

  • Nunca retornar entidades JPA directamente: usar DTOs en todas las respuestas.
  • Usar @ControllerAdvice con @ExceptionHandler para centralizar el manejo de errores.
  • Las validaciones de reglas del juego viven en GameValidatorService, no en el controller.
  • El cliente nunca hace restTemplate.getForObject(...) sin un bloque try-catch: toda llamada al server tiene fallback.
  • Configurar timeout del RestTemplate o WebClient explícitamente en la configuración del cliente.
  • Usar @Transactional en los métodos de servicio que modifican estado persistido.
  • H2 habilitado en application-dev.yml con spring.h2.console.enabled: true — nunca en el perfil de producción.
