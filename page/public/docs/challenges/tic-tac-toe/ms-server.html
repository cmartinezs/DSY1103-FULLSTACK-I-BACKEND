MS Server — gato-server

Puerto 8080
02.1

Tipos de partida

NO_TIME

Sin límite de tiempo

No hay restricción de tiempo por turno. El jugador puede tomarse todo el tiempo que necesite. La partida sólo termina por victoria, empate o abandono.

Campo: turnTimeoutSeconds: null

TIMED

Con límite de tiempo

Cada turno tiene un máximo de segundos. Si el jugador en turno no mueve a tiempo, pierde automáticamente la partida. El server detecta el timeout en cada consulta de estado o intento de movimiento.

Campo: turnTimeoutSeconds: 30 (mínimo 10 seg, máximo 300 seg)

Detección de timeout

El server no requiere un scheduler activo. La detección es lazy: al recibir cualquier request sobre una partida TIMED en curso, el server calcula si el tiempo del turno actual expiró comparando lastMoveAt (o startedAt para el primer movimiento) con el momento actual.

  • Si el tiempo expiró → la partida pasa a FINISHED, el jugador en turno pierde, y se retorna la respuesta con winner correspondiente.
  • El campo lastMoveAt se actualiza en cada movimiento válido.
  • El campo remainingSeconds puede incluirse en la respuesta de estado para que el cliente informe al jugador.
02.2

Modelo de dominio

Entidad: Game

  • id — Long, generado automáticamente
  • playerXId — Long, jugador que crea la partida (rol X)
  • playerOId — Long nullable, jugador que se une (rol O)
  • board — String de 9 chars: X, O, . (posiciones 0–8)
  • currentTurn — Enum: X | O
  • status — Enum: WAITING | IN_PROGRESS | FINISHED
  • winner — Enum nullable: X | O | DRAW | TIMEOUT
  • gameType — Enum: NO_TIME | TIMED
  • turnTimeoutSeconds — Integer nullable (sólo si gameType = TIMED)
  • lastMoveAt — LocalDateTime, actualizado en cada jugada
  • createdAt — LocalDateTime
  • startedAt — LocalDateTime, cuando el segundo jugador se une

Entidad: RegisteredClient

Representa un MS Cliente autorizado a usar este server. Se crea automáticamente en el primer arranque del cliente.

  • id — Long, generado automáticamente
  • clientId — String único, identifica al MS Cliente (ej: gato-client-1)
  • clientSecret — String, hasheado con BCrypt en el server
  • baseUrl — String, URL base del cliente (ej: http://localhost:8081)
  • registeredAt — LocalDateTime
  • active — Boolean

El server usa esta tabla como UserDetailsService para Spring Security: el clientId es el username y el clientSecret hasheado es el password. Migración Flyway obligatoria.

02.3

Reglas de negocio obligatorias

Validaciones de movimiento (en orden)

  1. La partida existe → 404 si no.
  2. La partida está en estado IN_PROGRESS → 422 si está WAITING o FINISHED.
  3. Para partidas TIMED: verificar si el turno expiró → si expiró, finalizar y retornar resultado.
  4. El jugador es participante de la partida (X u O) → 403 si no.
  5. Es el turno del jugador que mueve → 400 con mensaje descriptivo.
  6. La posición es válida (0–8) → 400 si está fuera de rango.
  7. La casilla no está ocupada → 400 con mensaje descriptivo.

Detección de fin de partida

Tras cada movimiento válido, el server evalúa en orden:

  • ¿Línea ganadora? (8 combinaciones: 3 filas, 3 columnas, 2 diagonales) → winner = X|O, status = FINISHED
  • ¿Todas las casillas ocupadas sin ganador? → winner = DRAW, status = FINISHED
  • Ninguna condición → cambiar turno, actualizar lastMoveAt, continuar.
02.4

Endpoints

Clic en cada endpoint para ver ejemplos de entrada/salida.

Gestión de partidas — /api/games
POST /api/games ▶ Crea una partida. El creador es el jugador X. Se especifica el tipo NO_TIME o TIMED.
Request Body — partida sin tiempo
{
  "playerXId": 42,
  "gameType": "NO_TIME"
}
Request Body — partida temporizada
{
  "playerXId": 42,
  "gameType": "TIMED",
  "turnTimeoutSeconds": 30
}
Response 201 Created
{
  "id": 1,
  "playerXId": 42,
  "playerOId": null,
  "board": ".........",
  "status": "WAITING",
  "currentTurn": "X",
  "gameType": "TIMED",
  "turnTimeoutSeconds": 30,
  "winner": null
}
GET /api/games ▶ Lista partidas. Soporta filtros por status y gameType.
Query Params (opcionales)
?status=WAITING
?status=IN_PROGRESS
?gameType=TIMED
?gameType=NO_TIME
Response 200 OK
[
  {
    "id": 1,
    "status": "WAITING",
    "gameType": "TIMED",
    "turnTimeoutSeconds": 30,
    "playerXId": 42,
    "playerOId": null
  }
]
GET /api/games/{gameId} ▶ Estado completo de la partida. En partidas TIMED incluye remainingSeconds. Detecta timeout lazy.

Registro de MS Clientes — /api/clients
POST /api/clients/register ▶ Endpoint público. Registra un MS Cliente autorizado. Lo llama automáticamente el cliente al arrancar. Si ya existe, actualiza baseUrl y retorna 200.
Request Body
{
  "clientId":     "gato-client-1",
  "clientSecret": "s3cr3t-client-1",
  "baseUrl":      "http://localhost:8081"
}
Comportamiento
· Si clientId no existe → crea, hashea secret → 201
· Si clientId ya existe → actualiza baseUrl → 200
· El server usa clientId/clientSecret
  como UserDetails para Spring Security
Response 201 Created
{
  "clientId":      "gato-client-1",
  "baseUrl":       "http://localhost:8081",
  "registeredAt": "2025-06-01T10:00:00",
  "message":       "Cliente registrado correctamente"
}
Response 200 OK (ya existía)
{
  "clientId": "gato-client-1",
  "message": "Cliente ya registrado, baseUrl actualizada"
}
Importante: Este es el único endpoint del server que no requiere autenticación. Todos los demás endpoints del server exigen el header Authorization: Basic {clientId:clientSecret} con credenciales de un MS Cliente registrado. Sin credenciales válidas → 401 Unauthorized.
